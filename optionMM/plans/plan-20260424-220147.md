# Exchange Calendar and Trading-Time Expiry

## Summary
Add an exchange-specific trading calendar and trading-session model backed by SQLite, seeded from YAML, and use it to compute Black-76 `T` from remaining tradable seconds. Black-76 will receive `T = remaining_trading_days / 252.0`, where one trading day equals that exchange's total configured session seconds.

## Key Changes
- Add non-hot-path calendar types and calculator in `common_lib`.
- Extend config parsing with YAML bootstrap sections for `exchange_calendars` and `exchange_trading_times`.
- Extend SQLite schema with exchange calendar and trading session tables.
- Seed YAML into SQLite at startup, reload runtime calendar/session state from SQLite, and fail startup when required exchange data is missing.
- Replace cached option `T` refresh logic with calendar-derived `T` while keeping pricer hot-path arrays unchanged.

## Test Plan
- Unit-test SHFE session totals, intraday remaining time, night sessions, holiday skipping, and per-exchange independence.
- Extend repository tests for calendar/session persistence and reload.
- Run focused calendar, repository, Black-76, option strategy, and simple engine tests.

## Assumptions
- YAML is the bootstrap source; SQLite is the runtime source after startup.
- Annualization is trading days divided by 252.
- Calendar maintenance API/UI is out of scope for this pass.
